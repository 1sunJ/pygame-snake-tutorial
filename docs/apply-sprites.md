# 스프라이트를 게임 코드에 적용하기

`pygame.draw.rect`로 네모를 칠하던 방식을 PNG 이미지를 붙이는 방식으로 바꾼 기록입니다.
리소스 제작 과정은 [sprite-assets.md](sprite-assets.md)에 따로 정리되어 있습니다.

---

## 1. 무엇이 바뀌었나

| 파일 | 변경 |
|---|---|
| `settings.py` | 내부 해상도 / 창 크기 분리, 색상 상수 정리, 폰트 크기 추가 |
| `renderer.py` | 네모 그리기 → 스프라이트 붙이기, 칸 모양 판별, 2배 확대 |
| `snake_game.py` | **변경 없음** |
| `main.py` | **변경 없음** |
| `tools/make_sprites.py` | `CELL` 32 → 16 (게임 코드 아님, 리소스 생성 도구) |
| `assets/sprites/*.png` | 16x16으로 재생성 |

게임 로직과 진입점을 건드리지 않은 게 핵심입니다.
`renderer.py` 맨 위에 적혀 있던 "그리기 방식을 바꿔도 게임 로직에 영향을 주지 않는다"는
설계가 실제로 지켜지는지 시험해 본 셈인데, 그대로 통과했습니다.

---

## 2. `settings.py`

### 내부 해상도와 창 크기를 분리했습니다

```python
CELL_SIZE = 16          # 스프라이트 한 장 = 칸 하나
SCALE     = 2           # 확대 배율. 반드시 정수

VIEW_W       = COLS * CELL_SIZE        # 내부 가로 320
VIEW_BOARD_H = ROWS * CELL_SIZE        # 내부 판 높이 320
FOOTER_H     = 18                      # 내부 하단 표기 영역
VIEW_H       = VIEW_BOARD_H + FOOTER_H # 내부 전체 338

WIDTH  = VIEW_W * SCALE   # 창 640
HEIGHT = VIEW_H * SCALE   # 창 676
```

**픽셀아트는 낮은 해상도로 그린 뒤 정수배로 확대해야 합니다.**
처음에는 32px 스프라이트를 640 창에 1:1로 그렸는데, 기술적 조건
(각진 경계, 안티에일리어싱 없음, 4단계 색)은 다 맞았는데도 픽셀아트로
보이지 않았습니다. 픽셀이 화면 픽셀과 1:1이라 너무 작아서 안 보였기 때문입니다.

그림을 16px로 줄이고 화면 전체를 2배 확대하니 그림 1픽셀이 화면에서
2x2 덩어리가 됩니다. 창 크기도 격자 수도 그대로인데 느낌이 완전히 달라집니다.

`main.py`는 `WIDTH`/`HEIGHT`만 쓰기 때문에 **한 줄도 안 고쳤습니다.**

### 사라진 상수

| 상수 | 이유 |
|---|---|
| `BLACK` | 배경이 계산해서 그리는 방식이 됨. 메뉴 바탕은 `BG`(숯빛)로 통일 |
| `RED` | 음식 네모를 그릴 때만 쓰던 색인데 사과 이미지로 대체됨 |
| `VIGNETTE` | 부드러운 그라데이션을 걷어내면서 같이 제거 |

`GREEN`은 살아남았지만 값이 바뀌었습니다. 뱀을 그리는 데는 더 이상 안 쓰이고
닉네임 입력 화면과 랭킹 화면의 강조 글자에만 쓰이는데, 스프라이트와
색을 맞춰야 따로 놀지 않습니다.

`WHITE`도 순백(255,255,255)에서 살짝 낮췄습니다.
어두운 판 위의 순백은 눈이 피로하고, 픽셀아트에서는 대비가 과해 보입니다.

### 색상 상수 전체

| 상수 | 값 | 쓰이는 곳 |
|---|---|---|
| `BG` | `(26, 21, 17)` | 게임 오버 / 랭킹 화면 바탕 |
| `GREEN` | `(79, 194, 89)` | 강조 글자 (닉네임, 내 점수) |
| `WHITE` | `(240, 236, 228)` | 일반 글자 |
| `BOARD` | `(38, 32, 26)` | 판 바탕 |
| `BOARD_DIM` | `(32, 27, 22)` | 가장자리 쪽 어두운 바탕 (점무늬로 섞임) |
| `BOARD_DOT` | `(60, 52, 42)` | 칸 모서리 점 |
| `FRAME` | `(24, 20, 16)` | 판 바깥 테두리 |
| `FRAME_LINE` | `(60, 51, 41)` | 테두리 안쪽 가는 선 |
| `FOOTER_BG` | `(18, 15, 12)` | 하단 표기 영역 바탕 |
| `FOOTER_TEXT` | `(110, 98, 84)` | 하단 표기 글자 |

스프라이트 색은 여기 없습니다. 그림에 이미 박혀 있어서
`tools/make_sprites.py` 위쪽 팔레트에 있습니다.

### 글자 크기도 내부 기준입니다

```python
FONT_BIG   = 19   # 화면에서는 38px처럼 보임
FONT_SMALL = 14
FONT_TINY  = 9    # 하단 제작자 표기
```

**글자도 내부 해상도에 그려야 합니다.** 창 해상도에 그리면 글자만 곱게 나와서
나머지와 결이 안 맞습니다. 작게 그려서 같이 확대하면 글자의 픽셀도 굵어져
자연스럽게 어울립니다. 별도 픽셀 폰트 파일이 필요 없다는 게 이 방식의 덤입니다.

### 안티에일리어싱은 껐습니다

`font.render(text, False, color)` — 두 번째 인자가 안티에일리어싱 여부입니다.
켜면 글자 경계에 중간색이 섞여 부드러워지는데, 각진 픽셀아트 위에서
그 매끈함이 혼자 튑니다.

### 창 아래 제작자 표기 영역

표기를 판 위에 겹쳐 그리면 뱀이 그 위를 지나갑니다.
그래서 창을 `FOOTER_H`만큼 키우고 판 아래에 따로 영역을 뒀습니다.
메뉴 화면의 중앙 정렬 기준도 `VIEW_H`가 아니라 `VIEW_BOARD_H`입니다.
안 그러면 글자 뭉치가 표기 영역 쪽으로 밀려 내려갑니다.

문구는 `settings.py`의 `CREDIT`과 `COPYRIGHT`에 있습니다.

## 3. `renderer.py`

### 3-0. 파일 구조

위에서부터 순서대로 이렇게 생겼습니다.

| 이름 | 종류 | 하는 일 |
|---|---|---|
| `ASSETS` | 상수 | `assets/` 폴더의 절대 경로 |
| `DIR_ANGLE` | 상수 | 진행 방향 → 회전 각도 (3-4) |
| `CORNER_ANGLE` | 상수 | 코너가 이어지는 두 방향 → 회전 각도 (3-4) |
| `BAYER4` | 상수 | 점무늬 배치표. 가장자리 어둡게 처리에 씀 (3-2) |
| `_delta(a, b)` | 함수 | `b`에서 `a`로 향하는 방향 벡터. 칸 판별에 씀 |
| `Renderer.__init__` | 메서드 | 내부 화면 · 폰트 · 스프라이트 · 배경을 한 번에 준비 |
| `_load(name)` | 메서드 | 스프라이트 PNG 한 장 읽기 (3-1) |
| `_build_board()` | 메서드 | 판 배경 한 장을 계산해서 만들기 (3-2) |
| `_present()` | 메서드 | 내부 화면을 2배 확대해 창에 붙이기 (3-2-1) |
| `_draw_footer()` | 메서드 | 판 아래 제작자 표기 그리기 |
| `_segment(snake, i)` | 메서드 | 칸 하나가 머리/몸통/코너/꼬리 중 뭔지 판별 (3-3) |
| `draw(...)` | 메서드 | 게임 화면 |
| `_center_text(...)` | 메서드 | 가로 중앙 정렬 글자 |
| `draw_name_input(...)` | 메서드 | 닉네임 입력 화면 |
| `draw_ranking(...)` | 메서드 | 랭킹 화면 |

`draw` / `draw_name_input` / `draw_ranking` 세 개만 `main.py`가 부릅니다.
나머지는 전부 내부용이라 이름 앞에 `_`가 붙어 있습니다.

### 3-0-1. 그림은 두 단계로 그린다

```python
self.view = pygame.Surface((VIEW_W, VIEW_H))   # 320x338, 실제로 그리는 곳
```

`__init__`에서 내부 화면을 하나 만들어 두고, 모든 그리기는 여기에 합니다.
`self.screen`(창)에 직접 그리는 곳은 `_present()` 한 곳뿐입니다.

**이 구분을 지켜야 합니다.** 실수로 `self.screen`에 뭔가 직접 그리면
그것만 확대되지 않아 다른 요소보다 곱게 나오고, 픽셀 크기가 안 맞아 튑니다.

### 3-1. 이미지는 시작할 때 한 번만 읽는다

```python
self.head = self._load("snake_head.png")
```

`pygame.image.load`를 `draw()` 안에서 호출하면 **매 프레임 디스크를 읽습니다.**
초당 10~20번 파일을 여는 셈이라 게임이 눈에 띄게 끊깁니다.
`__init__`에서 한 번만 읽어 두고 재사용합니다.

이어 붙인 `.convert_alpha()`는 이미지를 화면과 같은 픽셀 형식으로 미리 변환합니다.
이걸 빼면 붙일 때마다 형식 변환이 일어나 몇 배 느려집니다.

> `convert_alpha()`는 화면이 만들어진 뒤에만 호출할 수 있습니다.
> `main.py`가 `set_mode()`를 먼저 부르고 `Renderer`를 만들기 때문에 문제없습니다.

### 3-2. 배경은 이미지가 아니라 코드로 그린다

배경은 파일이 없습니다. `_build_board()`가 시작할 때 한 장을 만들어 둡니다.
평평한 바탕 + 칸 모서리 점 + 가장자리 어둡게 + 테두리로 구성됩니다.

처음엔 반복 타일 이미지를 썼는데 걷어냈습니다.
**400칸이 반복되면서 배경이 물러나지 않고 뱀 하나 사과 하나와 시선을 다퉜습니다.**
플레이어가 배경에서 실제로 필요한 정보는 "머리와 사과가 같은 줄인가" 하나뿐이라
칸 모서리 점만 남기니 해결됐습니다.

파일이 사라져서 배경은 격자 크기가 바뀌어도 알아서 따라옵니다.
`CELL_SIZE`에 묶여 있는 건 이제 스프라이트 5장뿐입니다.

### 가장자리를 어둡게 하는 방법 — 그라데이션 대신 점무늬

```python
t = (중심에서의 거리 비율) ** 2.2
if t > (BAYER4[y & 3][x & 3] + 0.5) / 16.0:
    board.set_at((x, y), BOARD_DIM)
else:
    board.set_at((x, y), BOARD)
```

**부드러운 그라데이션은 픽셀아트가 가장 피하는 것입니다.**
연속적인 색 변화가 있으면 아무리 스프라이트를 각지게 그려도 배경에서 티가 납니다.

그래서 색 두 개만 쓰고, 어느 쪽을 칠할지를 4x4 베이어 행렬로 정합니다.
점무늬가 섞이면서 중간 밝기처럼 보이는데, 확대하면 그 점이 눈에 보여서
오히려 픽셀아트다운 질감이 됩니다.

> **알파를 쓰다가 크게 데인 부분입니다.**
> 처음에는 검은 반투명 판(`SRCALPHA`)을 만들어 `smoothscale`로 확대한 뒤
> 판 위에 덮는 방식이었습니다. 그런데 **알파를 가진 표면을 smoothscale로
> 확대하는 조합이 실제 디스플레이 픽셀 포맷에서 깨져서, 판이 통째로
> 하얗게** 나왔습니다.
>
> 더 나쁜 건 헤드리스(`SDL_VIDEODRIVER=dummy`) 테스트에서는 멀쩡했다는 점입니다.
> 검사를 통과했는데 실제 창에서는 화면이 하얬습니다.
>
> 교훈: **알파와 화면 픽셀 포맷이 얽히는 코드는 헤드리스 검사만으로는 부족합니다.**
> 실제 드라이버로 한 프레임 저장해서 눈으로 봐야 합니다.
> (단, 저장할 때도 알파가 0으로 나가 화면이 하얗게 찍힐 수 있습니다.
>  `surface.convert(24)`로 알파를 버리고 저장해야 실제 화면과 같은 그림이 나옵니다.)

### 3-2-1. 그리고 2배로 확대해서 창에 붙인다

```python
pygame.transform.scale(self.view, (WIDTH, HEIGHT), self.screen)
```

`transform.scale`은 최근접 방식이라 픽셀이 흐려지지 않고 그대로 네모로 커집니다.
**`smoothscale`을 쓰면 부드럽게 뭉개져서 픽셀아트가 아니게 됩니다.**
이름이 비슷해서 헷갈리기 쉬운데 정반대 결과가 나옵니다.

세 번째 인자로 대상 표면을 넘기면 새 표면을 만들지 않고 화면에 바로 씁니다.

판 아래 영역(`VIEW_BOARD_H`부터 아래)을 칠하고 좌우에 문구를 하나씩 놓습니다.

### 3-3. 칸마다 어떤 그림을 쓸지 판별하기

가장 중요한 부분입니다. 예전에는 뱀의 모든 칸을 똑같은 네모로 그렸지만,
이제는 칸마다 머리/몸통/코너/꼬리를 구분해야 합니다.

**앞뒤 이웃 칸을 보면 알 수 있습니다.**

```python
def _segment(self, snake, i):
    cur = snake[i]

    if i == 0:                                    # 머리
        return self.head, DIR_ANGLE[_delta(cur, snake[1])]

    if i == len(snake) - 1:                       # 꼬리
        return self.tail, DIR_ANGLE[_delta(snake[i - 1], cur)]

    to_head = _delta(snake[i - 1], cur)           # 머리 쪽 이웃 방향
    to_tail = _delta(snake[i + 1], cur)           # 꼬리 쪽 이웃 방향

    if to_head[0] == -to_tail[0] and to_head[1] == -to_tail[1]:
        return self.body, 0 if to_head[1] == 0 else 90   # 직선

    return self.corner, CORNER_ANGLE[frozenset({to_head, to_tail})]
```

판별 규칙을 정리하면 이렇습니다.

| 위치 | 판단 |
|---|---|
| `i == 0` | 머리. 뒤 칸에서 머리로 향하는 방향이 진행 방향 |
| `i == len-1` | 꼬리. 몸통이 붙어 있는 방향으로 회전 |
| 앞뒤 이웃이 정반대 | 직선 몸통. 세로면 90도 회전 |
| 그 외 | 코너. 열린 두 방향의 조합으로 각도 결정 |

**이 판별이 렌더러 안에서 끝나기 때문에 `snake_game.py`를 고칠 필요가 없습니다.**
게임 로직은 예전처럼 좌표 리스트만 넘겨주면 됩니다.

### 3-3-1. `draw()`의 그리는 순서

순서가 중요합니다. 나중에 그린 게 위에 덮입니다.

| 순서 | 무엇을 | 왜 |
|---|---|---|
| 1 | 미리 만든 배경 한 장 | 앞 프레임 잔상을 지우는 역할도 겸함 |
| 2 | 사과 | 뱀보다 먼저. 머리가 겹칠 때 뱀이 위로 와야 자연스러움 |
| 3 | 뱀 (칸마다 판별 + 회전) | |
| 4 | 점수 | 판 위에 얹음 |
| 5 | 하단 표기 | 판 바깥 영역 |
| 6 | `_present()` | 여기서 한 번에 2배 확대해 창으로 |

배경이 화면 전체를 덮으므로 예전 `screen.fill(BLACK)`은 필요 없어졌습니다.

### 3-4. 회전 규칙

원본 그림은 5장뿐이고, 나머지는 돌려서 만듭니다.

```python
DIR_ANGLE = {(1, 0): 0, (0, -1): 90, (-1, 0): 180, (0, 1): 270}

CORNER_ANGLE = {
    frozenset({(-1, 0), (0,  1)}):   0,   # 왼쪽 + 아래
    frozenset({(0,  1), (1,  0)}):  90,   # 아래 + 오른쪽
    frozenset({(1,  0), (0, -1)}): 180,   # 오른쪽 + 위
    frozenset({(0, -1), (-1, 0)}): 270,   # 위 + 왼쪽
}
```

`pygame.transform.rotate`는 **양수 각도가 반시계 방향**입니다.
오른쪽을 보는 머리를 90도 돌리면 위를 봅니다.

코너는 방향 두 개를 `frozenset`으로 묶어 열쇠로 씁니다.
"위 + 왼쪽"과 "왼쪽 + 위"가 같은 모양이어야 하는데,
집합을 쓰면 순서에 관계없이 같은 열쇠가 되므로 경우를 나눌 필요가 없습니다.

90도 단위 회전은 픽셀이 정확히 자리를 바꾸기만 해서 그림이 뭉개지지 않습니다.
매 프레임 회전하지만 16x16 이미지라 부담이 없습니다.

---

## 4. 확인한 것

- 여러 방향으로 24프레임을 돌려 예외 없이 그려지는지
- 머리/직선/코너/꼬리가 모두 등장하는 뱀에서 회전 열쇠가 다 맞는지
  (`CORNER_ANGLE`에 없는 조합이면 `KeyError`로 바로 터짐)
- 게임 화면, 닉네임 입력 화면, 랭킹 화면이 640x676에서 깨지지 않는지
- **실제 디스플레이 드라이버로** 세 화면을 저장해 눈으로 확인

마지막 항목이 중요합니다. 헤드리스 검사만 믿었다가 화면이 하얗게 나오는 걸
놓친 적이 있습니다.

시작 시간은 0.34초입니다. 배경 점무늬를 320x320 픽셀마다 계산하는 비용인데,
한 번만 하고 재사용하므로 게임 중에는 영향이 없습니다.

## 5. 알아두면 좋은 점

**리소스가 없으면 게임이 시작조차 못 합니다.**
예전에는 색만 있으면 그려졌지만 이제는 `assets/` 폴더가 필요합니다.
파일이 없으면 `Renderer`를 만드는 순간 예외가 납니다.
학습용이라 일부러 예외 처리를 넣지 않았습니다. 파일이 없으면 바로 알아채는 게 낫습니다.

**`CELL_SIZE`는 스프라이트 크기와 묶여 있습니다.**
20으로 바꾸면 16짜리 그림이 칸에 안 맞아 빈틈이 생깁니다.
바꾸려면 `tools/make_sprites.py`의 `CELL` 값을 함께 고치고 다시 뽑아야 합니다.
배경은 계산해서 그리므로 알아서 따라옵니다.

**`SCALE`은 반드시 정수여야 합니다.**
1.5 같은 값을 넣으면 그림 픽셀이 화면 픽셀 경계에 안 맞아 뭉개집니다.
창을 더 키우고 싶으면 3으로 올리면 됩니다 (960x1014).

**`main.py`의 속도 계산은 그대로입니다.**
격자 수가 같아서 초당 몇 칸 움직이는지는 변하지 않았습니다.
`FPS_INIT`도 손대지 않았습니다. 화면만 커졌을 뿐 게임 진행은 예전과 동일합니다.
